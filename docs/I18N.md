# i18n — la convención de claves

Tres idiomas: **`es` es la fuente de la verdad**, `en` y `pt` la siguen. Traducir está permitido;
"mejorar" el español del brief, no (`harness/05_diseno_y_ux.md` §4).

## 1. Dónde vive

```text
src/locales/
├─ namespaces.ts     NS.common · NS.auth  (namespaces por constante, nunca por string)
├─ resources.ts      LANGUAGES, DEFAULT_LANGUAGE y el objeto resources
├─ i18n.ts           init + sincronización de <html lang>
├─ es/  common.json · auth.json          ← la fuente de la verdad (135 claves en auth, 29 en common)
├─ en/  common.json · auth.json
└─ pt/  common.json · auth.json
```

`src/types/i18next.d.ts` deriva los tipos de los JSON de `es`. **Una clave que no existe no
compila**, y el corolario manda en todo el código: **no hay claves dinámicas**. `t(variable)` no
compila; una variante se resuelve con un mapa explícito `valor → clave literal`.

## 2. Cómo se nombra una clave

`<sección>.<pantalla o campo>.<parte>` dentro del namespace del módulo:

| Forma | Ejemplo | Cuándo |
| --- | --- | --- |
| `shared.*` | `shared.google_button`, `shared.back_to_login` | texto que repiten varias pantallas del módulo |
| `shared.fields.<campo>.{label,placeholder,hint,options}` | `shared.fields.city.options.lima` | etiquetas de campo, que son las mismas en todos los formularios |
| `<feature>.*` | `login.submit`, `register.note` | texto de una sola pantalla |
| `<feature>.<estado>.{title,description,action}` | `reset_password.expired.title` | cada estado con su acción al lado |
| `errors.<meta_code en snake_case>` | `errors.invalid_credentials`, `errors.rate_limited` | **un `meta.code` del contrato = una clave** |
| `validation.<campo>_<motivo>` | `validation.password_too_short` | mensajes de Zod, que se guardan como clave y no como texto |

Reglas que no se negocian:

1. **Una sección por feature**, más `shared`, `errors` y `validation`. Nada de claves sueltas en la
   raíz del namespace.
2. **Los mensajes de un schema Zod son claves**, no texto (`03_` §12). Quien los pinta los pasa por
   `t()`: el traductor compartido `src/modules/auth/hooks/use_auth_message`.
3. **Las claves que puede llevar un mensaje de formulario están declaradas** en `AUTH_MESSAGE_KEYS`
   (`src/modules/auth/utils/messages`). Lo que no esté ahí se pinta como `errors.validation_error`:
   así una clave cruda del backend nunca llega a la pantalla.
4. **Interpolación con `{{nombre}}`** y el nombre en inglés: `errors.rate_limited` usa
   `{{seconds}}`. Si el dato puede faltar, hay una clave hermana sin número — `errors.retry_later`
   existe exactamente por eso.
5. **Añadir una clave es añadirla en los tres JSON** en el mismo commit.
   `src/__tests__/locales/resources.test.ts` compara los tres árboles y se pone rojo si falta una.

## 3. Los 12 `meta.code` del contrato, y su clave

| `meta.code` | Clave | Interpola |
| --- | --- | --- |
| `TOKEN_INVALID` | `errors.token_invalid` | — |
| `INVALID_CREDENTIALS` | `errors.invalid_credentials` | — |
| `UNAUTHENTICATED` | `errors.unauthenticated` | — |
| `SESSION_EXPIRED` | `errors.session_expired` | — |
| `EMAIL_NOT_VERIFIED` | `errors.email_not_verified` | — |
| `NOT_FOUND` | `errors.not_found` | — |
| `EMAIL_ALREADY_REGISTERED` | `errors.email_already_registered` | — |
| `ACCOUNT_USES_GOOGLE` | `errors.account_uses_google` | — |
| `VALIDATION_ERROR` | `errors.validation_error` | — |
| `RESEND_COOLDOWN` | `errors.resend_cooldown` | `{{seconds}}` |
| `RATE_LIMITED` | `errors.rate_limited` | `{{seconds}}` |
| `INTERNAL_ERROR` | `errors.internal_error` | — |

Más tres que no son códigos: `errors.network` (el interceptor no tuvo respuesta, `status === 0`),
`errors.retry_later` (un `429` sin `meta.retry_after_seconds`) y `errors.unknown` (código sin
documentar). El mapa vive en `src/modules/auth/utils/auth_error_message` y está tipado como
`Record<ApiErrorCode, clave>`: **si el contrato añade un código, el build se cae hasta que se añada
su clave**.

## 4. Las claves que manda el backend en `meta.fields`

El `422` trae `{"email": "auth.errors.email_invalid"}`: claves de i18n ya montadas, con el
namespace por delante y en un formato que este repo no puede pasar a `t()`. La traducción a clave
tipada es `toAuthMessageKey` (`src/modules/auth/utils/messages`), y es **el único** sitio que lo
hace. Lo que no está en el mapa cae en `errors.validation_error`.

La lista completa que manda el backend **sigue sin documentar** en `harness/04_contrato_api_auth.md`
§5, que solo nombra `auth.errors.email_invalid`. Cuando el equipo de service la publique, se amplía
ese mapa y nada más.

## 5. Cómo se consume

```tsx
const { t } = useTranslation(NS.auth);          // namespace por constante, nunca "auth"
t("login.submit");                              // clave tipada
t("errors.rate_limited", { seconds: 45 });      // interpolación
```

`<html lang>` se sincroniza con el idioma activo (`src/locales/i18n.ts:36`), la preferencia se
guarda en `localStorage` bajo `LOCAL_STORAGE_KEYS.LANGUAGE` y el selector vive en el layout de auth,
así que las 7 pantallas se pueden cambiar de idioma sin salir de ellas. Comprobado en el navegador
en las tres lenguas: ninguna pantalla enseña una clave cruda ni un `{{seconds}}` sin sustituir.
