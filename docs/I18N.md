# Languages and translations

The application supports Spanish (`es`), English (`en`), and Portuguese (`pt`). Spanish is the default and the source for translation types. Central configuration lives in `src/locales/`; each language separates `common` and `auth` JSON resources.

`NS` in `src/locales/namespaces.ts` contains valid namespace names. `resources.ts` loads all six files and declares supported languages. `i18n.ts` initializes i18next, detects the browser preference, and updates the document's `lang` attribute. The preference is retained under the centralized `LOCAL_STORAGE_KEYS.LANGUAGE` key.

Types in `src/types/i18next.d.ts` derive from the Spanish resources. Invalid keys must fail compilation. To add a phrase, define its key in the appropriate namespace file in all three languages, then use the namespace constant and a valid key in the component.

```tsx
const { t } = useTranslation(NS.common);
t("catalog.title");
```

Forms retain Zod validation keys rather than visible copy. API messages become translated messages through authentication or the affected module's logic. Do not present technical backend descriptions directly as UI copy without deciding how to translate them.

`src/__tests__/locales/resources.test.ts` compares keys across the three languages for each namespace and checks the auth error-code set documented in `src/constants/api_error_codes/index.ts`. Run `pnpm test:unit` for that check.
