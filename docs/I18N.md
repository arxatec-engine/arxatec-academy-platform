# Idiomas y traducciones

La aplicación ofrece español (`es`), inglés (`en`) y portugués (`pt`). Español es el idioma predeterminado y fuente de los tipos de traducción. La configuración central vive en `src/locales/` y los JSON de cada idioma separan `common` y `auth`.

`NS` en `src/locales/namespaces.ts` contiene los nombres válidos de namespace. `resources.ts` carga los seis archivos y declara los idiomas admitidos. `i18n.ts` inicializa i18next, detecta la preferencia del navegador y actualiza el atributo `lang` del documento. La preferencia se conserva con la clave centralizada `LOCAL_STORAGE_KEYS.LANGUAGE`.

Los tipos de `src/types/i18next.d.ts` derivan de los recursos españoles. Una clave incorrecta debe detectarse al compilar. Para agregar una frase, define la clave en el archivo del namespace correspondiente en los tres idiomas y usa la constante del namespace y una clave válida en el componente.

```tsx
const { t } = useTranslation(NS.common);
t("catalog.title");
```

Los formularios mantienen las claves de validación Zod en lugar de texto visible. Los mensajes de API se convierten a mensajes traducidos mediante la lógica de autenticación o del módulo afectado; las descripciones técnicas del backend no se deben presentar directamente como contenido de interfaz sin decidir su traducción.

La prueba `src/__tests__/locales/resources.test.ts` compara las claves de los tres idiomas para cada namespace y comprueba el conjunto de códigos de error de auth que documenta `src/constants/api_error_codes/index.ts`. Ejecuta `pnpm test:unit` para esa comprobación.
